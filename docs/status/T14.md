## Exact source versus explicit policy

BOOTSTRAP §4.7 fixes the distance at **0.25 × ATR(14,5m)**. It does not specify
linkage, expiry, touch counting, serving side, or invalidation algorithm. Those
choices remain mandatory explicit `ZonePolicy` arguments; no null configuration
value is silently filled. Supported policies:

- `single_linkage` or deterministic greedy `complete_linkage`.
- `entry_episode` or `every_intersecting_bar` touch counting.
- `close_beyond_edge` or `source_only` invalidation.
- `source_side_else_creation_close`: use unanimous explicit layer sides, else
  locate support/resistance relative to an available formation-time close.
  No component voting or strength weights are introduced.
- `cluster_formation` or `oldest_component` freshness; no expiry unless an
  explicit maximum age is provided.

Formation is no earlier than every component's creation and actual receipt.
Closed-bar touches before formation are excluded. ATR is supplied in canonical
FEATURE_SCHEMA with its actual availability. All lifecycle calculations use
available closed bars; price-invalidated zones remain with `invalidated_at` for
auditing, while source-invalidated components disappear. Consumers must exclude
price-invalidated zones from new setup formation.

Upstream FVG ambiguity is retained from T11. This zone module can be used with
explicit source/lifecycle policies and independently verified sources, but
cannot resolve that ambiguity or certify T11's exact source definition.
